# 全国酒蔵マスター 全面再監査手順

更新日: 2026-09-21

## 目的
brewery_master を候補マスターとして一件ずつ再検証し、酒蔵の現存、製造主体、所在地、代表銘柄、公式Web、公式EC、重複を確定する。

## 基本原則
- 旧DBのURLや旧監査結果だけで確定しない。
- 公式サイトが見つからないことと、公式Webページが存在しないことを同義にしない。
- URLは推測で登録しない。
- 公式ECは実際に商品を購入できる取引ページを確認した場合だけ official_shop_exists=true とする。公式ホームページをECとして代用しない。
- 酒造組合への加盟・非加盟は収録条件にしない。
- **「公式サイトなし」は通常検索の結果では判定しない。下記の優先監査を完了した後だけ確定できる。**

## 監査順序
1. 酒蔵名・法人名・代表銘柄で通常検索し、既存URLも現行性を確認する。
2. 公式サイトが即座に確定できない場合は、通常検索を繰り返す前に「公式サイトなし判定・最優先チェック」へ移る。
3. 最優先チェックで得た外部リンクは、検索結果の表示だけで判断せず**実際の遷移先まで開く**。
4. 酒造組合、日本酒造組合中央会、自治体・観光協会等で現存・所在地・銘柄を突合する。
5. 公式ECは公式サイトとは別に、商品・価格・購入/決済導線・運営主体を確認する。
6. 同名法人・同名酒蔵・県跨ぎ・旧称・移転・休廃業・事業承継を確認する。
7. 根拠URLと確認内容を full_reaudit_evidence / full_reaudit_notes に残す。
8. DB更新後に対象行を読み戻し、最後に集計件数を再取得する。

## 公式サイトなし判定・最優先チェック
公式サイトが通常検索ですぐ確定できない場合、次の4系統を**最優先・必須**で確認する。4系統を確認する前に official_site_url = null を確定してはならない。

### 優先1：古いドメイン・旧式Web
- HTTPのみ、www有無、旧ドメイン、旧社名ドメイン、ブランド名ドメインを検索する。
- ISP/プロバイダ領域、個人ホームページ系ホスティング、古いHTML、フレーム型サイトも対象とする。
- 現行の酒造組合・自治体等が旧式URLを蔵元Webとしてリンクしている場合は重要な公式性根拠とする。

### 優先2：酒造組合・業界団体の蔵元リンク
- 都道府県酒造組合、日本酒造組合中央会、地域酒造組合等の蔵元紹介ページを必ず開く。
- 「公式サイト」「ホームページ」「Web Site」「蔵元HP」等の外部リンクを**遷移先まで確認する**。
- 団体ページにURL文字列がなくても、リンクボタン・画像リンク等を確認する。

### 優先3：自治体・公的観光サイトの外部リンク
- 市区町村、都道府県、公式観光協会、地域産品等の公的ページを確認する。
- 酒蔵紹介ページにある「公式サイト」「ホームページ」等の外部リンクを**遷移先まで確認する**。
- 自治体側が古い公式URLを保持しているケースもあるため、リンク切れの場合もドメイン名を再検索する。

### 優先4：共有URL・短縮URLの遷移先
- ユーザー提供の share.google、短縮URL、Google共有URL等はURL文字列だけで判断しない。
- **必ず可能な限り最終遷移先まで追跡する。**
- 遷移先で酒蔵名、法人名、所在地、銘柄、連絡先を確認し、酒造組合・自治体・JSS等と突合する。
- 共有URLから新しい公式Web候補が見つかった場合は、既存の「公式サイトなし」判定を再監査する。

### 補完：逆引き検索
上記4系統で確定しない場合、代表銘柄、住所、電話番号、旧称、旧法人名を組み合わせて逆引きする。

## 「公式サイトなし」の確定条件
上記の**優先1〜4をすべて確認し、補完検索まで行っても公式Webを確定できない場合に限り** official_site_url を null とする。

その場合は必ず:
- full_reaudit_notes に「最優先チェック1〜4・補完検索実施済み／公式Web確定できず」と明記する。
- full_reaudit_evidence に確認した酒造組合・自治体・業界団体等の主要ソースを保存する。
- URL候補があるが公式性を確定できない場合は推測登録せず、候補と判断理由を notes に残す。

## 判定
- verified: 酒蔵の現存・主体・所在地等を十分な根拠で確認。
- needs_review: 主体、所在地、現存、重複等に重要な不確実性が残る。
- duplicate_candidate: 同一実体の重複可能性が高い。
- inactive_candidate: 休廃業等の可能性があり追加確認が必要。
- pending: 未監査。

## 監査単位
原則20件単位。各バッチで「取得 → 外部確認 → DB更新 → 全件読み戻し → 集計再取得」までを1セットとする。
