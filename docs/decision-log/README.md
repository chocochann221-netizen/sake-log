# 和酒ログ Decision Log

**Version:** 1.0  
**Status:** Living document  
**Purpose:** 和酒ログで「何を決めたか」「なぜ決めたか」「現在どの決定が有効か」を残す正本。

> 実装・ProductDesign・仕様判断で矛盾が生じた場合、原則として本Decision Logの最新のACTIVEな決定を優先する。過去の決定は削除せず、変更理由と履歴を残す。

## Status
- 🔒 **ACTIVE** — 現在有効な決定
- 🟡 **FUTURE** — 将来実装・検討
- 🟠 **UNDECIDED** — 方針未確定
- 🚀 **POST-LAUNCH P0** — 公開後の最優先項目
- ⚪ **SUPERSEDED** — 後のDecisionにより改定済み

---

## Product philosophy

### DL-001｜和酒ログの原点
**Status: 🔒 ACTIVE**

日本酒を「調べるアプリ」ではなく「出会った酒を残すアプリ」とする。

基本体験は **起動 → 撮影 → 銘柄確認 → 飲んだ記録 → 酒ログ → 知る → また飲む**。ラベル認識そのものを主役にせず、技術は体験を支える裏方とする。

### DL-002｜AIを前面に出さない
**Status: 🔒 ACTIVE**

ユーザー向け画面ではAI感を出さない。「AIが学習した」等の表現を主役にせず、日本酒・酒蔵・土地・思い出とのつながりを優先する。

### DL-003｜SNSを主役にしない
**Status: 🔒 ACTIVE**

フォロー・いいね・投稿数競争を中心とするSNSにはしない。主役は「あの日、どこで、誰と、何を飲んだか」という個人の記録。

### DL-004｜世界観
**Status: 🔒 ACTIVE**

ログハウス、木の温かさ、自然、日本の四季を基本世界観とする。春夏秋冬で別世界にせず、同じ場所が季節によって変化する感覚を重視する。

### DL-005｜ProductDesignを先に確定する
**Status: 🔒 ACTIVE**

原則を **ProductDesignでUX/UI確定 → ユーザー確認・承認 → 実装** とする。実装側が独自判断で承認済みデザインを変更しない。

## Core experience

### DL-006｜撮影体験
**Status: 🔒 ACTIVE**

表ラベル撮影 → 確認 → 裏ラベル任意撮影 → 候補 → 確認・修正 → 飲酒記録 → 保存を基本導線とする。表・裏ラベルを保存可能とし、入力途中の情報を失わない設計を優先する。

### DL-007｜認識結果はユーザーが修正できる
**Status: 🔒 ACTIVE**

認識結果を絶対視しない。複数候補を提示し、ユーザーが修正できる。修正結果は辞書・マスター改善につなげる。

### DL-008｜飲酒記録
**Status: 🔒 ACTIVE**

日時・場所等を記録できる。「誰と飲んだ」は任意入力。時間表示を過剰に強調しない。写真や思い出も酒の記録につなげられる設計とする。

### DL-009｜Ver.1の主導線
**Status: 🔒 ACTIVE**

主要領域をホーム / MY LOG / 知識の蔵とし、撮影へ明確にアクセスできるようにする。機能を増やしすぎて「日本酒を撮って残す」体験を弱めない。

### DL-010｜知識の蔵
**Status: 🔒 ACTIVE**

精米歩合、米の品種、造り方、味わい、保存方法等を初心者にも分かる形で提供する。単なる辞典ではなく、飲んだ酒から知識へ、知識から次の酒との出会いへつながる構造を目指す。

## Prefecture / regional experience

### DL-011｜47都道府県ページ
**Status: 🔒 ACTIVE**

基本構造を **ヒーロー → 短い導入 → 地域 → 食 → 酒蔵一覧** とする。写真比率・余白・文字位置・スクロールリズム・酒蔵カード等に共通設計を持たせつつ、各県の個性は残す。

### DL-012｜都道府県ページはProductDesign主導
**Status: 🔒 ACTIVE**

既存県を含めProductDesign基準で整理する。承認済みのマスター構造を全国展開し、見本と実装で意図せずデザインを変えない。

### DL-013｜都道府県ページの画像
**Status: 🔒 ACTIVE（改定済み）**

当面の間、都道府県ページでは実写を使用せず、AIによる作成画像を使用する。

ただし「AI生成画像らしさ」を前面に出さない。自然な光、素材に応じた光沢・反射、現実的な質感・陰影、過度に鮮やかすぎない色、不自然に整いすぎない構図、自然な空気感を品質基準とする。

**改定履歴:** 旧方針「実写優先、出典・撮影者・ライセンスを管理」はSUPERSEDED。47都道府県展開の制作速度・統一感と権利確認負荷を考慮し現行方針へ変更。

### DL-014｜Ver.1では酒蔵写真を掲載しない
**Status: 🔒 ACTIVE**

酒蔵外観・商品写真・ロゴをVer.1では原則掲載しない。利用実績を作った後、必要に応じて酒蔵へ正式に写真利用許諾を依頼する。

## Brewery master / commerce

### DL-015｜全国酒蔵マスターの収録基準
**Status: 🔒 ACTIVE**

酒造組合への加盟・非加盟を掲載条件にしない。現在確認できる日本酒の製造者・酒蔵・製造拠点を可能な限り収録する。組合名簿は網羅性確認の調査ソースとして扱う。

### DL-016｜酒蔵マスターの役割
**Status: 🔒 ACTIVE**

酒蔵マスターは一覧だけでなく **ラベル認識 → 銘柄 → 酒蔵 → 地域 → 購入 → 知識** をつなぐ基盤データとする。出典・確認日・再確認状態等も管理する。

### DL-017｜酒蔵にも利益が残る購入導線
**Status: 🔒 ACTIVE**

購入・アフィリエイト導線では可能な限り酒蔵側にも利益が残る構造を優先する。蔵元EC、公開アフィリエイト、専用URL、専用クーポン、手動集計型提携、酒販店経由等を調査する。

### DL-018｜イベント
**Status: 🟡 FUTURE**

イベント名、主催者、日程、場所、費用、定員、写真、主催者コメント、出品銘柄、連絡先、リンク等を扱える構造を想定する。和酒ログ自体をイベント申込サービスにはしない。

## Pricing / monetization / discovery

### DL-023｜無料・課金ユーザーの基本方針
**Status: 🔒 ACTIVE**

無料ユーザーでも和酒ログの基本体験が成立することを原則とする。課金は基本体験を奪うためではなく、保存容量や将来の拡張機能など、より深く利用するための追加価値として設計する。

### DL-024｜広告を掲載しない
**Status: 🔒 ACTIVE**

和酒ログには広告を掲載しない。広告収益のためにユーザーの閲覧・行動を誘導する設計も行わない。

### DL-025｜「おすすめアプリ」にしない
**Status: 🔒 ACTIVE**

飲酒履歴から特定の酒を強く推薦するサービスにはしない。嗜好だけをもとに推薦を繰り返すことで飲む酒が偏り、新しい日本酒との出会いを狭めることを避ける。

和酒ログは「好みを固定する」のではなく「酒との出会いを残す」ことを優先する。

### DL-026｜分析機能
**Status: 🟡 FUTURE**

高度な分析はVer.1に含めない。将来実装する場合も、飲酒本数、地域、酒蔵、種類など自分の記録を振り返るための最低限の分析を中心とし、推薦アルゴリズムを主目的にしない。

### DL-027｜購入導線
**Status: 🚀 POST-LAUNCH P0**

購入導線を公開後の最優先アップデート項目とする。ラベルを撮影・記録した酒から **銘柄 → 酒蔵 → 購入先** へ自然につなげる。DL-017の方針とセットで扱う。

### DL-028｜記録・写真保存容量
**Status: 🟠 UNDECIDED**

無料・課金ユーザーの記録可能件数、表ラベル写真、裏ラベル写真、思い出写真、長期保存等の上限は要検討。ユーザー体験とStorage等の実運用コストを確認して決定する。

### DL-029｜限定コンテンツ
**Status: 🟡 FUTURE**

課金ユーザー向け限定コンテンツは将来検討項目とする。Ver.1の課金成立のために無理に限定コンテンツを作らない。

## Decision Log運用ルール

1. **過去の決定を消さない。** 方針変更時は旧決定をSUPERSEDEDとして履歴を残す。
2. **最新のACTIVEを現在の正本とする。** 過去チャット・旧資料と矛盾する場合は最新のACTIVE Decisionを優先する。
3. **ProductDesign・実装・テストで参照する。** 重要な仕様判断前に該当Decisionを確認する。
4. **変更理由を残す。** 結論だけでなく、なぜ変更したかを記録する。
5. **重要な新決定はDL番号を付与する。** 料金変更など運用上の小変更と、プロダクト思想・UXを変えるDecisionを区別する。
6. **未決定事項を決定済みに見せない。** UNDECIDED/FUTUREを明示する。
7. **和酒ログの思想を守る。** 技術や短期的な最適化が、酒との出会い・記録・文化への接続という基本体験を損なわないか確認する。
